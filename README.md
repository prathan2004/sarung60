# SARUNG · ระบบติดตามเป้าหมายการออม

เว็บภาษาไทยสำหรับสมาชิกและผู้ดูแล ใช้ HTML, CSS, Vanilla JavaScript และ Chart.js หน้าเว็บและ API proxy อยู่บน Netlify ส่วน Apps Script ตรวจสิทธิ์และบันทึกข้อมูลใน Google Sheets กับ Google Drive

## กติกาการออม

- เป้าหมายเริ่มที่ 2,000 บาท และเพิ่ม 2,000 บาทต่อผู้ติดตามที่มีอายุครบ 11 ปี คำนวณจากวันเกิดและวันที่ปัจจุบันใน Asia/Bangkok
- ระบบคำนวณใหม่ทุกครั้งที่เปิดภาพรวมหรือรายงาน และคืนยอดใหม่ทันทีเมื่อบันทึกการเปลี่ยนแปลงผู้ติดตาม ประวัติการชำระเงินยังอ้างอิงรายการเดิม
- ยอดคงเหลือคือเป้าหมายหักยอดอนุมัติแล้ว โดยต่ำสุดเป็นศูนย์ ส่วนเกินแสดงแยกและกราฟแสดงสูงสุด 100% ยอดรอตรวจสอบแสดงแยกจากสถานะการออม
- ภาพรวมผู้ดูแลรวมทุกบัญชี รวมถึงบัญชีที่ปิดใช้งาน เปอร์เซ็นต์โครงการใช้ผลรวมยอดอนุมัติที่นับเข้าเป้าหมายของสมาชิกแต่ละคน หารด้วยเป้าหมายรวม
- Admin ต้องตรวจยอดเข้าบัญชีจริงจากธนาคารก่อนยืนยันอนุมัติ เว็บเก็บผลการตรวจที่ Admin บันทึก ไม่มีการเชื่อมต่อธนาคารอัตโนมัติ
- วันเกิด 29 กุมภาพันธ์จะเปลี่ยนอายุในวันที่ 1 มีนาคมเมื่อปีนั้นไม่มี 29 กุมภาพันธ์
- รหัสผ่านสมาชิกใช้ขั้นต่ำ 4 ตัวอักษรเมื่อสร้างบัญชี รีเซ็ต หรือเปลี่ยนรหัสผ่าน บัญชี Admin ใช้ขั้นต่ำ 12 ตัวอักษร

## โครงสร้าง

| ตำแหน่ง | หน้าที่ |
|---|---|
| `index.html`, `login.html`, `dashboard.html`, `payment.html`, `history.html`, `profile.html` | หน้าเริ่มต้นและหน้าสมาชิก |
| `admin/` | ล็อกอิน ภาพรวม สมาชิก ผู้ติดตาม คิวตรวจสอบ รายละเอียด รายงาน Audit Logs และ Settings |
| `assets/` | CSS สำหรับมือถือและเดสก์ท็อป รวมถึงโมดูล JavaScript |
| `google-apps-script/` | Manifest และโค้ดตั้งค่า ฐานข้อมูล บัญชี สิทธิ์ ผู้ติดตาม สลิป และรายงาน |
| `netlify/functions/api.mjs` | API same-origin, scrypt, คุกกี้เซสชัน และตัวกลางเชื่อม Apps Script |
| `netlify.toml`, `scripts/build.mjs`, `scripts/bootstrap.mjs` | ตั้งค่า deploy, สร้างไฟล์เว็บ และเตรียมบัญชี Admin |
| `tests/system.test.mjs` | ทดสอบกติกา ยอดเงิน สิทธิ์ ไฟล์ และ API ด้วยระบบจำลองใน Node.js |

## 1. สร้างฐานข้อมูลในบัญชี Google

1. สร้าง Google Sheets ว่างใน My Drive ของบัญชีที่จะรัน Apps Script เลือกไฟล์ที่แชร์เฉพาะเจ้าของ และคัดลอก Spreadsheet ID จาก URL ส่วนที่อยู่ระหว่าง `/d/` กับ `/edit`
2. สร้าง Apps Script Project ใหม่ในบัญชีเดียวกัน คัดลอกไฟล์ `.gs` ทั้งหมดจาก `google-apps-script/` ไปยังโปรเจกต์ เปิด **Show “appsscript.json” manifest file in editor** ที่ **Project Settings** แล้วแทน manifest ด้วยไฟล์ในโฟลเดอร์เดียวกัน ถ้าใช้ Standard Google Cloud Project ให้เปิด Google Sheets API ใน Cloud Console ด้วย [คู่มือ Advanced Google Services](https://developers.google.com/apps-script/guides/services/advanced)
3. ที่เทอร์มินัลภายในโฟลเดอร์นี้ ใช้ Node.js 22 ขึ้นไป รัน `node scripts/bootstrap.mjs` แล้วใส่ชื่อผู้ใช้ Admin และรหัสผ่านอย่างน้อย 12 ตัวอักษร เก็บผลไว้ในที่จัดเก็บข้อมูลลับ เพราะต้องใช้ค่าบางส่วนใน Netlify ด้วย
4. ที่ **Project Settings → Script Properties** ใส่ `SHEET_ID`, `PROXY_SECRET`, `SESSION_SECRET`, `BOOTSTRAP_USERNAME` และ `BOOTSTRAP_HASH` โดยใช้ค่าจากขั้นตอนข้างต้น
5. เลือกฟังก์ชัน `setup` ใน Apps Script Editor กด **Run** และอนุญาตสิทธิ์ ในนามบัญชีเจ้าของตรวจว่าแท็บฐานข้อมูลสร้างสำเร็จ ใน Drive จะมี `SavingSystem/PaymentSlips` โดยตั้งโฟลเดอร์หลักเป็น Private และสร้างโฟลเดอร์ปี/เดือนเมื่อมีการบันทึกรายการแรก ตรวจในหน้าจอแชร์ของ Drive ว่าเจ้าของเป็นผู้มีสิทธิ์ตามที่ตั้งใจ
6. เลือก **Deploy → New deployment → Web app** ตั้ง **Execute as** เป็น **Me** และ **Who has access** เป็น **Anyone** คัดลอก URL ที่ลงท้ายด้วย `/exec` ไปตั้งเป็น `GAS_URL` ใน Netlify การตั้งนี้เปิดให้ Netlify ติดต่อ Web App ได้ ส่วน API ตรวจ `PROXY_SECRET` จากเซิร์ฟเวอร์ก่อนดำเนินการ และบังคับใช้สิทธิ์บัญชีสำหรับข้อมูลสมาชิก ถ้าองค์กรบล็อก deployment แบบนี้ สถาปัตยกรรมปัจจุบันจะเชื่อมต่อไม่ได้ [คู่มือ Apps Script Web Apps](https://developers.google.com/apps-script/guides/web)
7. เมื่อแก้โค้ด Apps Script ให้ไปที่ **Deploy → Manage deployments → Edit → New version** และเก็บ URL เดิมไว้

`setup` สร้างหัวตารางตาม schema และลบค่า bootstrap หลังสร้าง Admin สำเร็จ เรียกซ้ำเพื่อตรวจโครงสร้างและสร้างทรัพยากรที่ขาดได้ รหัสผ่าน Admin เปลี่ยนได้ที่ Settings หลังล็อกอิน

### แท็บฐานข้อมูล

| แท็บ | ข้อมูล |
|---|---|
| Settings | ชื่อโครงการและกติกาการออม |
| Members / Admins | บัญชี สถานะ และ verifier ของรหัสผ่าน |
| Followers | ผู้ติดตามและวันเกิด ค.ศ. รูปแบบ `YYYY-MM-DD` |
| Payments | จำนวนเงิน วันที่แจ้ง สถานะ ผู้ตรวจสอบ เหตุผล และ ID ไฟล์ Drive |
| AuditLogs | ผู้ดำเนินการ เวลา รายการที่เปลี่ยน และรายละเอียด |
| Sessions | เซสชันที่เพิกถอนได้และเวลาหมดอายุ |
| Uploads | ส่วนของไฟล์ที่อัปโหลดชั่วคราวและล้างตามอายุ staging |

ระบบเขียนข้อมูลสำคัญภายใต้ Script Lock และบันทึกการเปลี่ยนแปลงหลักพร้อม Audit Log ใน Sheets batch เดียว [เอกสาร Sheets batchUpdate](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate)

## 2. Deploy ที่ Netlify

1. นำซอร์สขึ้น Git repo ของคุณ แล้วเลือก **Add new project → Import an existing project** ใน Netlify เชื่อม repo และตั้ง root เป็นโฟลเดอร์ที่มี `netlify.toml` ไฟล์นี้กำหนดคำสั่ง build เป็น `node scripts/build.mjs`, publish directory เป็น `dist` และ Functions directory เป็น `netlify/functions`
2. ตั้ง Environment Variables ใน Functions scope ของ production ถ้าแพ็กเกจรองรับการเลือก scope แล้ว deploy ใหม่

   | ตัวแปร | ค่า |
   |---|---|
   | `GAS_URL` | URL Apps Script `/exec` |
   | `PROXY_SECRET` | ค่าเดียวกับ Script Properties |
   | `PASSWORD_PEPPER` | ค่าจาก bootstrap ซึ่งเก็บใน Netlify เท่านั้น |

3. เปิด URL แบบ HTTPS แล้วไปที่ `/admin/login.html` เมื่อล็อกอินแล้ว เพิ่มบัญชีสมาชิกจากเมนู **สมาชิก** สมาชิกเข้าที่ `/login.html` ควรใช้ Sheets, Drive และ secrets แยกสำหรับการทดสอบ

   [เอกสาร Netlify Functions Environment Variables](https://docs.netlify.com/build/functions/environment-variables/)

Netlify ต้อง deploy ทั้งหน้าคงที่และ Functions จากโปรเจกต์นี้ การอัปโหลดเฉพาะโฟลเดอร์ `dist` จะเปิดหน้าเว็บได้ แต่ไม่มี API สำหรับล็อกอินและบันทึกข้อมูล

## 3. การทดสอบ

```sh
node scripts/build.mjs
node --test tests/system.test.mjs
```

ชุดทดสอบใช้ข้อมูลที่สร้างขึ้นในหน่วยความจำและตอบ HTTP upstream แบบจำลอง ครอบคลุมอายุ 10 และ 11 ปี วันเกิดตามเวลาไทย การเพิ่ม/แก้/ลบผู้ติดตาม ยอดแจ้ง 500 บาท การอนุมัติและปฏิเสธ ยอดเกินเป้าหมาย สิทธิ์สลิปและการแอบส่ง role การล็อกอิน/หมดอายุ/ล็อกเอาต์ การเปลี่ยนรหัสผ่าน การตรวจไฟล์ การส่งและอ่านครบ 5 MiB และการส่งซ้ำหลังการเขียนล้มเหลว

ก่อนใช้กับข้อมูลจริง ให้ตรวจบน staging ผ่าน HTTPS ด้วย Admin และสมาชิกทดสอบ 2 บัญชี

1. เข้าระบบแต่ละบทบาทและตรวจว่าเข้าสู่แดชบอร์ดที่ถูกต้อง ออกจากระบบแล้วเปิดประวัติอีกครั้งเพื่อทดสอบการเพิกถอนเซสชัน
2. เพิ่มผู้ติดตามที่ยังอายุ 10 ปี จากนั้นแก้วันเกิดให้ครบ 11 ปี แล้วลบ ตรวจยอดใหม่ทั้งที่หน้าผู้ติดตาม หน้าสมาชิก และรายงาน CSV
3. ส่งสลิปทดสอบ 500 บาท ตรวจว่า Pending เพิ่มที่แดชบอร์ด ขณะที่ยอด Approved ยังเป็น 0 ทดสอบไฟล์ JPEG, PNG และ WEBP ที่เปิดได้จริง รวมถึงไฟล์ใกล้ขนาดสูงสุด
4. เปิดสลิปผ่าน Admin บันทึกผลอนุมัติและตรวจยอดใหม่ ทดสอบปฏิเสธรายการถัดไป ตรวจหมายเหตุ และลองเปิดสลิปเก่าในทั้งสองสถานะ
5. ใช้บัญชีสมาชิกคนที่สองลองเปิดรายการของสมาชิกคนแรก แล้วตรวจว่า Drive ไม่เปิดสลิปให้คนที่มีลิงก์ และไฟล์ใน Sheets ชี้ไปที่โฟลเดอร์ปี/เดือนตามที่คาด
6. เปิดทุกหน้าในจอมือถือและเดสก์ท็อป ตรวจว่ากราฟแสดงผลและไฟล์ CSV เปิดได้ในโปรแกรมตารางคำนวณ

## ข้อจำกัดและการดูแล

- เซสชันมีอายุ 8 ชั่วโมงและใช้คุกกี้ HttpOnly, Secure, SameSite=Strict การออกจากระบบ เปลี่ยน/รีเซ็ตรหัสผ่าน และปิดบัญชีจะเพิกถอนเซสชันที่เกี่ยวข้อง การสลับบัญชีบนเบราว์เซอร์เดียวกันใช้คุกกี้ชื่อเดียวกัน
- การจำกัดการลองล็อกอินใช้ CacheService แบบ best-effort ตามชื่อผู้ใช้และ IP จึงขึ้นกับอายุและการคงอยู่ของแคช Google ระบบล็อกและการอ่าน Sheets มีโควตาและเหมาะกับโครงการที่มีปริมาณงานจำกัด ผู้ที่มีสิทธิ์แก้ไข Sheets หรือ Script โดยตรงสามารถเปลี่ยนข้อมูลนอกกติกาของเว็บได้
- เบราว์เซอร์ตรวจชนิด ขนาด และการเปิดภาพตัวอย่าง ส่วนเซิร์ฟเวอร์ตรวจขนาดและโครงสร้างหัวไฟล์กับ MIME การตรวจนี้ไม่มีการสแกนมัลแวร์หรือถอดรหัสภาพทุกพิกเซล สลิปถูกแบ่งเป็นชิ้น 2 MiB ทั้งตอนอัปโหลดและเปิดดูเพื่อให้ payload อยู่ในเพดาน Netlify [ขีดจำกัด Netlify Functions](https://docs.netlify.com/build/functions/configuration/)
- ข้อมูลไฟล์และตารางใช้คนละบริการ การเขียนล้มเหลวระหว่างสองบริการอาจทิ้งไฟล์ที่ไม่มีแถวอ้างอิง การส่งซ้ำด้วย PaymentID เดิมจะคืนรายการที่สร้างแล้ว และทริกเกอร์รายวันจะล้างไฟล์ชั่วคราวที่มีแถวอ้างอิงเมื่อครบ 24 ชั่วโมง ควรตรวจไฟล์กำพร้าหากมีเหตุขัดข้องต่อเนื่อง
- Charts โหลด Chart.js เวอร์ชันคงที่จาก CDN ส่วนตัวเลขและแถบความคืบหน้าแสดงได้เมื่อกราฟโหลดไม่ได้ ฟอนต์ Google มีฟอนต์สำรอง
- เก็บค่า secrets นอกซอร์ส รักษาขอบเขตการแชร์ Sheets และ Drive สำรองข้อมูลอย่างเหมาะสม การหมุน `SESSION_SECRET` ทำให้เซสชันเดิมหมดอายุ การเปลี่ยน `PASSWORD_PEPPER` ต้องตั้งรหัสผ่านใหม่ให้ทุกบัญชีรวมถึง Admin
- การตรวจในเครื่องครอบคลุมซอร์สและโครงสร้างไฟล์เว็บ การเชื่อมกับบริการ Google และ Netlify จริง รวมถึงการแสดงผลในเบราว์เซอร์ ต้องตรวจจาก deployment ของโครงการ
